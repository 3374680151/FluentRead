# FluentRead 网页版 + 嵌入 SDK 需求整理（V2，2026-10-30）

> 目标：让**访客打开你的网站就自带插件全部能力，不装任何东西**；站长加一行 `<script>` 即可接入。
> 本文是 V2 需求基线，取代 `web-embed-sdk-design-20261030` 的架构假设（保留其功能映射与验收方式）。
> 依据：对 `web/`、`src/features/`（28 模块）、`src/providers/translation/`（40+ 供应商）的全量代码勘查。

---

## 零、三个必须先说的结论

1. **不是"没有设计"，是"设计没法上线"。** `web/` 已有 5 个页面 + `fluentread-sdk.js`（34KB）+
   本地 Node 转发服务，功能是真的（真实上游、真实词书）。但全仓**没有任何部署配置**
   （无 Dockerfile / compose / vercel.json），只能 `pnpm web:start` 跑在 `127.0.0.1:8787`。
   所以"站长加一行 script"目前**兑现不了**——那行 script 指向的地址没人能访问。
2. **访客仍然要自己配密钥。** AI 词典、AI 讲解、AI 起草都依赖 API Key，而 Key 存在**每个访客自己的
   localStorage**。这正是你想消灭的负担：用户装不装插件不重要了，但要填 Key，等于换了个门槛。
3. **收藏的单词跨不了站。** SDK 的词书写入发生在**宿主页面的 origin**（Dexie/IndexedDB 按源隔离），
   所以在 `docs.你的域名.com` 收的词，`learn.html`（另一个源）看不到。`web/README.md` 里
   "与本站学习中心同库互通"这句是错的，必须改。

另外：**你最在意的"写文档时翻译"，网页版目前没有入口。** `web/public/` 只有
`index`（文本翻译）/ `study`（句子精读）/ `learn`（复习）/ `services` / `settings`，
没有文档翻译工作台，也没有写作助手。

## 二、学习者视角：网页里最该有什么（用户故事 + 验收）

按"读英文资料 → 写中文文档"的真实动线排序，每条都给可验收的判定标准。

| # | 用户故事 | 验收标准 |
| --- | --- | --- |
| 1 | 读英文文档，**选中就出译文**，不打断阅读 | 鼠标松开 ≤ 400ms 出现气泡；Esc / 点空白关闭；不遮挡选区 |
| 2 | 选中的是**单词**时，给我词典而不是机翻 | 有音标、词性、中文义项、例句；未收录词如实标注"机器翻译兜底" |
| 3 | 看不懂的词**一键收藏**，自动带上下文原句 | 收藏项含原句（≤500 字）+ 来源 URL + 页面标题 |
| 4 | 收藏的词**能复习**，复习时看得懂当初为什么收 | 翻卡展示挖空原句；两键评分写入调度；到期队列正确 |
| 5 | 写中文文档时，**选中中文就能出英文**，风格可调 | 支持正式/简洁/学术三档；结果可编辑后回填，不直接覆盖原文 |
| 6 | 写英文时**不确定就查**，不离开编辑区 | 编辑区内触发（`///` 或快捷键）；返回译文 + 可选替换 |
| 7 | 全篇**术语一致**（同一个词始终同一译法） | 术语库命中率 100% 优先于模型输出；冲突时提示 |
| 8 | 整篇英文文档**双语对照读** | 段落级左右/上下对照，保留原文样式；滚动同步 |
| 9 | **跟读**：点词朗读，语速可调 | 单词/句子/译文均可读；语速 0.5–2.0；可中断 |
| 10 | 知道自己**学了多少** | 首页可见：收藏总数 / 待复习 / 已掌握 / 今日新学 |
| 11 | **全程零配置** | 首次访问到完成第一次划词翻译，不出现任何"填 API Key"弹窗 |
| 12 | 换设备/换站点，**词书还在** | 同一浏览器跨站可见；登录后跨设备可见 |

第 11 条是这次改造的**总闸门**：任何需要访客自己配置的路径都算不通过。

## 三、架构必须改的 6 处

| # | 现状 | 问题 | 目标 |
| --- | --- | --- | --- |
| D1 | `web/server.ts` SSR 服务，`127.0.0.1:8787`，无部署配置 | 没人能访问 | 拆成**静态站（CDN）+ 独立 API 服务（容器）**；补 Dockerfile、compose、环境变量模板、健康检查 |
| D2 | 密钥存访客 `localStorage` | 每个访客都要配 Key，违背零配置 | 密钥归**站长**（服务端环境变量）；访客侧不出现任何 Key 输入；可选"自带 Key"作为高级项 |
| D3 | 词书写宿主页 origin 的 IndexedDB | 跨站不互通，README 说法有误 | 词书写**服务端**，用匿名 visitorId（cookie/localStorage）关联；登录后升级为账号 |
| D4 | 免费线路是公开网页接口 + DNR 改请求头 | 公网流量会被封、有 ToS 风险、无法限流 | 免费池**只在服务端跑**；对外只暴露统一 `/api/translate`；上游失败按序降级；官方 API 作为兜底 |
| D5 | 无鉴权、无配额 | 公开代理会被刷爆 | 站点 token（`data-fr-site`）+ 按 origin 配额 + 速率限制 + 超限友好降级 |
| D6 | `web/public` 无文档翻译、无写作助手 | 你的核心场景没入口 | 新增 `write.html`（写作台）与 `docs.html`（文档翻译）两个页面 |

补充：SDK 的 `serverUrl` 默认取 `script.src` 的 origin，方向对；但当前**必须**站长自建整套 Node 服务才可用，
改为"官方托管 API + 站长只需填站点 token"后，一行 script 才真正成立。

## 五、验收与迭代协议（≥5 轮）

每轮固定四步，**不允许抽样**——每轮把 P0 功能全部操作一遍：

1. **走查**：以访客身份，从空 profile 打开站点，按功能清单逐项操作；记录截图 + 控制台报错 + 网络失败。
2. **用户视角提意见**：只说"哪里不好用"，不解释实现。
3. **PM 定级**：P0 阻塞 / P1 体验 / P2 打磨，写进本轮清单。
4. **开发修复 + 回归**：修完重跑本轮全量走查，P0 未清零不进下一轮。

| 轮次 | 目标 | 走查范围 | 通过门槛 |
| --- | --- | --- | --- |
| R0 | 基线 | 全部 P0 | 拿到公网链接；缺陷清单 v0 |
| R1 | 零配置首译 | 全部 P0 | 冷启动到首译成功，0 次配置提示 |
| R2 | 读文档 | 读侧 P0+P1 | 气泡不挡内容、词典准确、收藏带上下文 |
| R3 | 写文档 | 写侧 P0+P1 | 中→外可用、术语一致、可回填 |
| R4 | 学习闭环 | 收藏→复习→跨站 | 跨站词书可见，调度正确 |
| R5 | 稳定性 | 全量 + 断网/超时/隐私模式/移动端 | 控制台零报错，超时有友好提示 |

## 六、需要你拍板的 3 件事（不定就没法开工）

1. **部署在哪？** 域名是什么、谁来托管（你的服务器 / Vercel / Cloudflare）。
   我这边没有任何部署凭据，只能产出可部署产物 + 一键命令。
2. **翻译额度谁付？** ① 站长统一 Key，访客免费（需配额防刷）② 平台池 + 按站点计费
   ③ 访客自带 Key（回到现在的老问题）。**推荐 ①**。
3. **词书要不要跨设备？** 要 → M3 必须做服务端 + 账号；不要 → 保持本地，但**跨站互通这条需求删掉**，
   并修正 README 的错误表述。
